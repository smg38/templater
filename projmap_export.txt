# templater

[![CI](https://github.com/OWNER/REPO/actions/workflows/test.yml/badge.svg)](https://github.com/OWNER/REPO/actions/workflows/test.yml)
[![ShellCheck](https://img.shields.io/badge/shellcheck-passing-brightgreen)](https://www.shellcheck.net/)

[![Version](https://img.shields.io/badge/version-3.2.0-blue.svg)](CHANGELOG.md)

Простой шаблонизатор для подстановки переменных окружения в текстовые
файлы. Поддерживает модификаторы (фильтры), автозагрузку `.env` и
автозапись `.out`. Не требует Python, Node.js или Jinja2 — только
POSIX-совместимые `bash`, `awk` и `coreutils`.

## Возможности

- `{{ VAR }}` — подстановка переменных окружения;
- фильтры-цепочки: `{{ VAR | lower | replace('-','_') | upper }}`;
- `default(...)` — значение по умолчанию;
- кодирование и хеширование: `b64encode`, `b64decode`, `sha256`, `md5`, `hexdump`, `urlencode`;
- строковые операции: `upper`, `lower`, `trim`, `quote`, `replace`, `substr`, `indent`;
- автопоиск `<template>.env` и запись результата в `<template>.out`;
- strict-режим `-s` для CI;
- чтение шаблона из stdin (`-`) и запись в stdout;
- **без `eval`** — значения переменных не исполняются как shell-код.

## Быстрый старт

`config.j3`:

```jinja
app: {{ APP_NAME | upper }}
greeting: {{ GREETING | default('hello') | quote }}
url: https://example.com/?q={{ GREETING | urlencode }}
token: {{ SECRET | b64encode }}
```

`config.env`:

```dotenv
APP_NAME=my-service
GREETING="hello world"
SECRET='s3cr3t'
```

Запуск:

```bash
templater config.j3
```

Результат — `config.out`:

```yaml
app: MY-SERVICE
greeting: 'hello world'
url: https://example.com/?q=hello%20world
token: czNjcjN0
```

## Синтаксис шаблонов

```
{{ VAR }}
{{ VAR | filter }}
{{ VAR | filter1 | filter2 | ... }}
```

Правила:

- имя переменной: `[A-Za-z_][A-Za-z0-9_]*`;
- между `{{` и именем допускаются пробелы;
- фильтры разделяются `|`, аргументы — в скобках, в одинарных или двойных кавычках;
- несколько плейсхолдеров в одной строке поддерживаются;
- неизвестный фильтр молча игнорируется;
- отсутствие переменной без `default(...)` → пустая строка + warning в stderr.

---

## Фильтры

| Фильтр | Аргументы | Пример |
|---|---|---|
| `default('V')` | строка | `{{ X \| default('n/a') }}` |
| `upper` / `lower` | — | `hello` → `HELLO` / `hello` |
| `trim` | — | `"  x  "` → `x` |
| `quote` | — | `it's` → `'it'\''s'` |
| `b64encode` / `b64decode` | — | `hi` → `aGk=` / обратно |
| `urlencode` | — | `a b/c` → `a%20b%2Fc` |
| `sha256` / `md5` | — | hex-дайджест |
| `hexdump` | — | `AB` → `4142` |
| `replace('A','B')` | две строки | `banana` → `bXnXnX` |
| `substr(N)` / `substr(N,M)` | числа | `abcdef`, 3 → `cdef` |
| `indent(N)` | число | сдвиг каждой строки на N пробелов |

Цепочки:

```jinja
{{ NAME | lower | replace('-','_') | upper }}
{{ TOKEN | default('x') | b64encode | sha256 }}
```

## Файл переменных `.env`

```dotenv
# комментарий
KEY=value
EMPTY=
WITH_SPACES="hello world"
LITERAL='$not_expanded'
MULTILINE="line1\nline2"
```

- `$VAR` **не** раскрывается (безопасность);
- переменные окружения процесса имеют приоритет над `.env`;
- для секретов: `chmod 600 *.env` и добавить `*.env` в `.gitignore`.

---

## Автопоиск `.env` и `.out`

При запуске `templater config.j3`:

1. если рядом есть `config.env` — загружается;
2. если `-o` не указан — результат пишется в `config.out`.

| Шаблон | Авто `.env` | Авто `.out` |
|---|---|---|
| `file.j3` | `file.env` | `file.out` |
| `dir/file.tpl` | `dir/file.env` | `dir/file.out` |
| `file` (без расширения) | `file.env` | `file.out` |
| `-` (stdin) | — | stdout |

---

## Ключи командной строки

| Ключ | Описание |
|---|---|
| `-e ENVFILE` | загрузить переменные из ENVFILE (отключает автопоиск `.env`) |
| `-o OUTPUT` | записать результат в OUTPUT (отключает автопоиск `.out`) |
| `-s` | strict: ошибка, если переменная не определена и нет `default` |
| `-h` | справка |

## Приоритеты

**Источники переменных** (высший → низший):

1. окружение процесса (`FOO=bar templater ...`);
2. `-e ENVFILE`;
3. `<template>.env` (автопоиск).

**Источники вывода:**

1. `-o OUTPUT`;
2. `<template>.out`;
3. stdout (только для stdin-шаблона).

## Примеры

### Базовая подстановка

```bash
echo 'Hello {{ NAME }}!' > hello.j3
echo 'NAME=World' > hello.env
templater hello.j3
cat hello.out          # Hello World!
```

### Окружение перебивает `.env`

```bash
NAME=Override templater hello.j3
cat hello.out          # Hello Override!
```

### Явные `-e` / `-o`

```bash
templater -e prod.env -o /etc/app/config.yml config.j3
```

### stdin → stdout

```bash
printf 'Hi {{ N }}\n' | N=you templater -
# Hi you
```

### Strict-режим в CI

```bash
templater -s config.j3 || exit $?
```

## Безопасность

- Скрипт **не использует `eval`** — значения переменных не исполняются.
- Значения передаются во внешние утилиты через `printf %s '...'` с корректным shell-квотингом.
- Имя файла-шаблона не попадает в `eval`.
- `.env` не раскрывает `$VAR`, `$(...)`, бэктики.
- Подробности: [docs/security.md](docs/security.md).

## Ограничения

- Нет условий (`{% if %}`) и циклов — это не Jinja2.

- Зависит от POSIX `awk` (проверено на gawk, mawk, busybox awk).

## FAQ

**Q: Чем отличается от `envsubst`?**
A: `envsubst` умеет только `$VAR`/`${VAR}`. Здесь — `{{ VAR }}`, фильтры,
`default(...)`, автопоиск `.env`/`.out`, strict-режим, безопасность без `eval`.

**Q: Почему результат пишется в `file.out`, а не в stdout?**
A: Чтобы `templater config.j3` была идемпотентной командой без пайпов.
Нужен stdout — используйте шаблон `-` или `-o /dev/stdout`.

**Q: `.env` не подхватился. Почему?**
A: Проверьте, что имена совпадают (`file.j3` ↔ `file.env`) и что не передан `-e`.

**Q: Как добавить свой фильтр?**
A: Добавьте `f_имя(v, arg)` в awk-блок `templater.sh` и ветку в `apply_filter`.
Подробности: [docs/filters.md](docs/filters.md).

# Формат .env

## Грамматика

```
line       := comment | blank | assignment
comment    := WS* '#' .*
blank      := WS*
assignment := WS* KEY WS* '=' VALUE
KEY        := [A-Za-z_][A-Za-z0-9_]*
VALUE      := bare | single_quoted | double_quoted
```

## Правила значений

| Форма | Что происходит |
|---|---|
| `KEY=value` | значение обрезается по краям |
| `KEY="a\nb"` | `\n` → перевод строки, `\t` → таб, `\"` → `"`, `\\` → `\` |
| `KEY='$x'` | буквально `$x`, без раскрытия |
| `KEY=` | пустая строка |

`$VAR`, `$(cmd)`, бэктики **не** раскрываются.

## Приоритет

Окружение процесса побеждает `.env`. Если `FOO` уже есть в окружении,
значение из `.env` не перезапишет его.

## Пример

```dotenv
# .env.example
APP_NAME=my-service
GREETING="hello world"
SECRET='s3cr3t'
INDENT=4
EMPTY=
```

# Фильтры — детали

## Синтаксис аргументов

- `filter` — без скобок;
- `filter(arg)` — один аргумент;
- `filter(a, b)` — два аргумента, разделитель — запятая;
- аргументы в одинарных (`'`) или двойных (`"`) кавычках; кавычки снимаются.

## Таблица

| Фильтр | Аргументы | Реализация | Замечание |
|---|---|---|---|
| `default` | строка | awk | срабатывает, только если значение пусто |
| `upper` / `lower` | — | awk `toupper`/`tolower` | ASCII |
| `trim` | — | awk `sub` | пробелы, табы, `\r`, `\n` |
| `quote` | — | awk | shell-safe: `'it'\''s'` |
| `b64encode` | — | `base64 \| tr -d '\n'` | без переносов |
| `b64decode` | — | `base64 -d` | ошибки → пусто |
| `urlencode` | — | awk | RFC 3986 (unreserved: `A-Za-z0-9._~-`) |
| `sha256` | — | `sha256sum`/`shasum` | hex |
| `md5` | — | `md5sum`/`md5` | hex |
| `hexdump` | — | `od -An -v -tx1` | без разделителей |
| `replace` | две строки | awk `gsub` | regex-aware |
| `substr` | 1 или 2 числа | awk `substr` | 1-based |
| `indent` | число | awk | добавляет N пробелов в начало каждой строки |

## Примеры

```jinja
{{ PASSWORD | default('changeme') }}
{{ USERNAME | lower | replace(' ','_') }}
{{ API_KEY | sha256 | substr(1, 16) }}
{{ CERT | indent(4) }}
```

# Безопасность

## Что защищено

1. **Нет `eval`** — значение переменной никогда не интерпретируется shell'ом.
2. **Shell-квотинг** — значения передаются во внешние команды через
   `printf %s '...'`, где одиночные кавычки экранированы.
3. **Имя файла** — не подставляется в `eval`; используется как аргумент awk.
4. **`.env` не раскрывает `$VAR`** — нет подстановки переменных внутри значений.

## Что НЕ защищено

- Если вы сами передаёте значение из недоверенного источника и оно
  попадает в `replace('A','B')` как regex — возможен ReDoS. Не
  используйте `replace` на недоверенных данных.
- Внешние утилиты (`base64`, `sha256sum`) вызываются через shell —
  их наличие и поведение вы должны контролировать.

## Рекомендации

- Для секретов: `chmod 600 *.env`, добавить `*.env` в `.gitignore`.
- В CI не храните секреты в `.env` — используйте secrets-механизм.
- Для недоверенных шаблонов используйте `-s` (strict), чтобы поймать
  неожиданные переменные.

## Отчёт об уязвимостях

Создайте issue с меткой `security` или напишите мейнтейнеру.

# templater — расширенное руководство

## Внутренности парсера

Плейсхолдер разбирается awk-скриптом в три этапа:

1. Регуляркой `\{\{[[:space:]]*[A-Za-z_][A-Za-z0-9_]*[[:space:]]*(\|[^{}]*)?\}\}`
   вырезается весь плейсхолдер из строки.
2. Из тела (`VAR | f1 | f2`) выделяется имя переменной и цепочка фильтров.
3. Цепочка фильтров применяется слева направо. `default(...)` учитывает
   вложенные скобки, `replace(...)` и `substr(...)` разбирают аргументы
   по запятой.

Значения берутся из `ENVIRON[]` — это безопасный доступ к переменным
окружения без `eval`.

## Расширение фильтрами

Фильтр — функция `f_имя(v, arg)` в awk-скрипте:

```awk
function f_reverse(v,   i, r) {
    r = ""
    for (i = length(v); i >= 1; i--) r = r substr(v, i, 1)
    return r
}
```

И ветка в `apply_filter`:

```awk

```
CLI args ──► getopts ──► envfile? ──► load .env ──► export (если не задано)

                │
                ▼

                │
                ▼
